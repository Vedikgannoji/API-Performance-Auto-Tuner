# v2.0.0b2 — Phase 11 checkpoint

This checkpoint preserves the working Phase 1–11 API monitoring proxy, explicit static/adaptive public-read caching, local dashboard, scenario runner and bounded telemetry exports. It is a prerelease for review, not a claim of completed performance qualification or the future end-to-end CLI developer product.

## Fixes

- Scenario output is reserved before any scenario submission. Existing files and invalid destinations prevent execution. Interrupted/uncertain submissions retain an incomplete marker and run ID so users can inspect the running proxy before retrying.
- Release evidence rejects duplicate fields, non-finite constants, excessive nesting, boolean schema versions and out-of-contract soak durations without crashing.

## Installation and usage

Use the attached wheel in a virtual environment with `python -m pip install PATH_TO_WHEEL`, then `autotuner --help`. Review README.md for complete upstream/proxy/monitoring startup commands. The `autotuner demo` upstream uses disposable RAM, not your application database.

The existing product requires explicit upstream and cache rule configuration. It does not discover project APIs, modify application/database code, provide interactive terminal menus or guarantee perfect API performance. Those are separate Phase 12–17 work, with measured goals and explicit supported-framework boundaries.

## Remaining limitations

Loopback and one worker only; bounded finite HTTP requests. No WebSockets or distributed consistency. The dashboard is bundled and optional. Observe mode serves no shared cached responses; caching requires approved rules and compatible public responses.

Current-source full soak, reference-host overhead qualification, hosted compatibility verification, owner license approval, registry identity and external pilots remain open. The strict release checker stays blocked. This checkpoint does not authorize uploading to PyPI or imply that a package with this name in a registry belongs to this repository.

## Release procedure

After stabilization tests and joint review, commit and push the frozen source. Use the manual Prepare beta distributions workflow to build artifacts from that commit. Verify the artifacts and their checksums, then create a **GitHub prerelease** with tag v2.0.0b2 at that exact commit and this document as its description. Do not mark it as the latest stable release. Do not claim reference-host qualification or independent pilots.

Registry publication is a separate gated step. No license is silently assigned. Retain the original phase evidence as historical evidence; any source-changing fixes require fresh qualification before a qualified product beta.
